# צופר חירום

אפליקציית התרעות (Android), עם השרתים, הממסר ואפליקציית הניהול שלה.

## החלקים

| תיקייה | מה זה | איפה רץ |
|---|---|---|
| `app/` | צופר חירום, האפליקציה | טלפונים (APK) |
| `server/` | השרת הראשי: מקורות ההתרעות, Firebase, אתר, מפה, הקלטות | Oracle (ירושלים), tzofar-app.duckdns.org |
| `cloudflare/` | השרת המשני (גיבוי) | Cloudflare Worker |
| `relay/` | ממסר צופר: גיבוי אחרון, טלפון בבית | טלפון Android 8.1 |
| `admin/` | ניהול צופר: בדיקת יישובים, הקראה וצלילים | הטלפון של טל |
| `editor/` | עריכת צופר: עריכת הנראות של המסכים ושליחת השינויים | הטלפון של טל |
| `tools/` | כלים להקלטות ולהגייה | — |

סדר הגיבוי: Oracle ← Cloudflare ← ממסר ← הטלפונים בודקים לבד.

## ענפים

`main` מכיל תמיד את הגרסה העדכנית של **כל** החלקים. כל חלק מתפרסם מהענף שלו:

| ענף | מה קורה כשמעלים אליו |
|---|---|
| `beta` | בטא של האפליקציה ("תעדכן") |
| `main` | גרסה ציבורית ("תשחרר") — רק כשהאפליקציה משתנה |
| `server` | השרת ב-Oracle מתעדכן לבד תוך 5 דקות |
| `cloudflare` | נפרס ל-Cloudflare |
| `relay` | גרסה חדשה של הממסר |
| `admin` | גרסה חדשה של ניהול צופר |
| `editor` | גרסה חדשה של עריכת צופר |
| `signing` | מפתחות החתימה (מוצפנים) — לא נוגעים |
| `pending-pwa-app` | עבודה על ה-PWA והאתר — נדחה להמשך |

**כלל:** כל שינוי בשרת, ב-Cloudflare, בממסר, בניהול צופר, בעריכת צופר או בכלים נכנס גם ל-`main` מיד, כדי שלא יהיו שוב עותקים ישנים. באפליקציה: העבודה נמצאת ב-`beta` ונכנסת ל-`main` כשמשחררים.

## עריכת צופר

העתק של מסכי צופר חירום (לא עובד באמת) לעריכת הנראות: לוחצים על רכיב, משנים צבע / גודל / טקסט / מיקום או כותבים הערה,
ושולחים את כל השינויים בבת אחת לשרת (`/api/design`, נשמר ב-`server/design.json`).
כשטל כותב "תטפל בעריכה": מריצים את `Design inbox` (`gh workflow run design-inbox.yml`), קוראים את השליחות מהלוג,
מבצעים בקוד של האפליקציה, ומעדכנים מצב (`-f id=… -f state=working|done -f msg=…`).
המסכים עצמם: `editor/src/main/assets/web/screens.js` – כשמסך באפליקציה משתנה, לעדכן גם אותו שם.
`editor` לא רשומה ב-`settings.gradle.kts` (שינוי שם בונה את צופר חירום) – הבנייה מוסיפה אותה.
